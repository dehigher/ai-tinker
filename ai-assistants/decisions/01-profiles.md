# 决策：4 个 Profile 的划分

## 结论

创建 4 个独立 Hermes profile：

| Profile 名（草案） | 角色 | 职责范围 |
|---|---|---|
| `life` | 生活助手 | 生活、装修、育儿、健康等日常任务 |
| `study` | 学习助手 | 基于指定学习素材，系统梳理、消化、整理知识 |
| `finance` | 理财助手 | 收集资讯、策略分析、理财建议 |
| `work` | 办公助手 | 工作相关任务，如整理表格、写文档 |

命名未最终拍板，实施时需要确认 `hermes profile create <name>` 的 name 是否要用英文（会自动生成命令别名，如 `life chat`），需要和用户确认最终命名。

## 模型分化策略

- **理财助手**：涉及策略分析、推理，建议配更强的推理模型。
- **学习助手**：知识消化整理需要较强理解和总结能力，同样建议配强模型。
- **办公助手**：整表格、写文档等任务偏机械，可以配更快更便宜的模型，控制成本。
- **生活助手**：日常对话为主，走默认模型即可。

具体型号（哪个 provider、哪个模型）留到实施阶段根据当时可用的模型和用户的 provider 账号情况决定，这里只定分化策略，不锁定具体型号。

## 创建方式

用 `hermes profile create <name>` 分别创建 4 个空白 profile（不用 `--clone`，因为角色差异大，没有必要共享初始配置）。创建后：

1. `<name> setup` 配置模型和 API key。
2. 按 `04-skill-sharing.md` 的策略把通用 skill symlink 进去。
3. 补充角色专属 skill（例如生活助手的"装修甲醛检测流程"这类，用户已有相关 memory/经验，应沉淀为 study/life 的专属 skill）。
4. 迁移/整理现有分散在默认 profile 里的、属于某个角色的 memory 片段（如果有）到对应新 profile。
