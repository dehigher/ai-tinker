# 决策：子任务流水线策略

## 背景

当某个助手要处理的单个任务太大时（例子：学习助手把"系统梳理一批学习素材"拆成"收集资料 → 消化理解 → 文档整理"三个阶段），需要多个子 agent 协作完成。

## 结论：默认用 `delegate_task`，不预先搭建常驻 kanban 队列

### 方式 1（默认采用）：单一 profile 内，`delegate_task` 临时派生子 agent

- 主 session 收到大任务后，按阶段 spawn 子 agent（可并行可串行），结果汇总回主 session，子 agent 用完即丢。
- 零配置成本，现在就能用。
- 适用场景：一次性大任务，比如"这批论文/资料系统梳理一下"。

### 方式 2（暂不实施）：profile 内常驻多角色 + kanban 工作队列

- 用 `kanban` toolset（Multi-agent work-queue，gated to workers）搭建持久任务队列，多个 worker agent 认领不同阶段的卡片。
- 适用场景：同一类流水线反复发生、需要跨会话持续追踪进度（例如"每天都有新素材进来，排队经过收集→消化→整理"）。
- 升级触发条件：发现方式 1 的"一次性委派"模式被同一类任务反复触发，且用户需要跨会话查看某个任务目前卡在哪个阶段。
- 代价：需要配套看板 UI 才能看到卡片状态（见 `03-dashboard.md` 的细粒度部分），复杂度和维护成本更高。

## 哪些助手当前最可能需要流水线

- **学习助手**：最可能，资料量大、阶段清晰（收集/消化/整理）。
- **办公助手**：偶尔可能需要，比如大报告 = 查资料 + 写初稿 + 排版。
- **生活助手 / 理财助手**：目前判断更偏单轮对话 + 工具调用，暂不需要拆解。
